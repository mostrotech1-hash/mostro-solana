# Security

This document covers the Solana program in `programs/mostro`. It states the security model as implemented today, the authorities involved, the known limitations, and how to report a vulnerability.

The program is deployed on devnet only. It has not been audited. Do not deploy it to mainnet in this state.

## Security model

| Property                                  | How the code provides it                                                                                                                                                                                                                                                                                |
| ----------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| User transactions need no protocol signer | PDAs sign every mint, burn-from-vault and transfer-from-vault with program seeds (`invoke_signed`). The buyer or seller signs; buys and `redeem_perk` also declare a `payer` signer that defaults to the buyer, so the self-paid case still has one signature                                           |
| Payer / buyer separation                  | `payer` is charged only for rent (`buyer_ata`, `receipt`, Core asset) and the Metaplex Core protocol fee. SOL, USDC and `$MOST` always leave `buyer`; tokens and the asset always go to `buyer`; KYC and pass ownership are checked against `buyer`. A sponsor cannot redirect a trade by paying for it |
| Funds move only through program paths     | `sol_vault` and `treasury` are system accounts at PDAs; only `sell_tokens` and `withdraw_treasury_sol` move lamports out of them. Token vaults have PDA authorities                                                                                                                                     |
| Integer safety                            | `overflow-checks = true` in release; curve, split and discount math run in `u128` with checked operations and return `MathOverflow` instead of panicking. Quotes compare against caller-provided slippage bounds                                                                                        |
| Fixed protocol accounts                   | `config`, `treasury` and `treasury_usdc` are PDAs with fixed seeds. `initialize_config` can be called once, and only by the program's upgrade authority (`program_data.upgrade_authority_address == payer`), so a stranger cannot front-run initialization                                              |
| Admin gating                              | `has_one = admin` on `Config` for every admin instruction. Artist instructions accept the artist's `authority` or the admin, with two exceptions below                                                                                                                                                  |
| Admin-only passes                         | `create_perk` with `kind == Pass` requires `signer == config.admin` (`Unauthorized` otherwise). Passes grant benefits across every artist, so an artist cannot issue one                                                                                                                                |
| Artist-only vault withdrawals             | `withdraw_artist_vault` takes `authority` with `has_one = authority` on `Artist` and no `config` account. The protocol admin has no path to an artist's revenue                                                                                                                                         |
| Protocol split floors                     | `create_perk` and `set_perk` require `burn_bps >= config.min_burn_bps`, `rewards_bps >= config.min_rewards_bps` and `burn + rewards <= 10_000` (`InvalidBps`). An artist cannot route 100% of a redeem to its own vault once floors are set                                                             |
| Pause switch                              | `config.paused` stops buys, sells and redeems in one transaction                                                                                                                                                                                                                                        |
| Admin rotation with cool-off              | `propose_admin` starts a timer (`admin_cooloff_secs`); `accept_admin` by the new key succeeds only after it; `cancel_admin_transfer` aborts                                                                                                                                                             |
| Oracle validation (price mode 1)          | Pyth account key, owner (Pyth receiver program), verification level `Full`, feed id, positive price, and staleness (`max_price_age_secs`) are all checked before use                                                                                                                                    |
| Oracle confidence                         | In price mode 1 the Pyth `conf` must be within 2% of `price` (`conf * 10_000 <= price * 200`), else `PriceUncertain`. A wide interval during a volatile minute blocks USDC buys instead of pricing them off a noisy quote                                                                               |
| Admin price expiry (price mode 0)         | The admin value is rejected with `PriceTooOld` when `now - config.price_updated_ts > admin_price_max_age_secs` (its own limit, 86,400 s on devnet; Pyth keeps `max_price_age_secs` = 300 s); a forgotten price cannot keep pricing USDC buys                                                            |
| Redeem price cap                          | `redeem_perk(nonce, max_paid)` fails with `SlippageExceeded` when the effective price exceeds the caller's cap, so a `set_perk` price change cannot overcharge a transaction signed against an older quote                                                                                              |
| Treasury rent floor                       | `initialize_config` funds `treasury` with `Rent::minimum_balance(0)` and `withdraw_treasury_sol` refuses to go below it (`InsufficientReserves`), so the PDA stays rent-exempt and cannot be reaped                                                                                                     |
| Artist handover                           | `set_artist` may change `authority` only when signed by the current authority; the admin can edit name, URI and active flag but cannot take over an artist (and so cannot reach its vault)                                                                                                              |
| Pass perks admin-owned                    | `create_perk` and `set_perk` on `kind == Pass` require the admin. A pass presented on redeem must also come from an active pass perk (`PerkInactive` otherwise), so retiring a tier retires its benefits                                                                                                |
| KYC gate                                  | When `config.kyc_required` is true, curve buys and sells need an admin-written `Kyc` with `approved == true` and `wallet == buyer` (or `seller`). Gating both sides keeps an unverified wallet from cashing out tokens it received by transfer                                                          |
| Perk integrity                            | `redeem_perk` checks `perk.artist`, `perk.mint`, `perk.collection` with `has_one`; the Core collection's update authority is the `artist` PDA, so only this program can mint into it                                                                                                                    |
| Pass integrity                            | A pass is accepted only if the buyer owns it, its update authority is the pass perk's collection, and that pass perk is active                                                                                                                                                                          |
| Replay safety                             | The asset PDA is seeded by a client nonce; Metaplex Core refuses to create an asset that already exists, so a resent transaction fails instead of double-charging                                                                                                                                       |
| Bounded strings                           | Name <= 32, symbol <= 10, URI <= 200 bytes, enforced on every write                                                                                                                                                                                                                                     |

## Authorities and keys

| Authority                    | Holder                                                                 | Scope                                                                                                                                                                                                                                                                   |
| ---------------------------- | ---------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Program upgrade authority    | Deployer keypair (hot key, `~/.config/solana/id.json` of the deployer) | Can replace the program binary                                                                                                                                                                                                                                          |
| `Config.admin`               | Same deployer keypair on devnet                                        | Pause. Set fee (max 10%), price mode, admin price, Pyth account and feed, pass benefits, split floors, `kyc_required`. Create curves, artists and Pass perks. Write KYC records. Withdraw treasury SOL and USDC. Edit any artist or perk. Cannot withdraw artist vaults |
| IDL authority                | Same deployer keypair                                                  | Can replace the on-chain IDL                                                                                                                                                                                                                                            |
| `Artist.authority`           | Wallet chosen at `create_artist`, changeable by `set_artist`           | Create and edit that artist's Music / Event / Merch perks (not passes) within the split floors, mark receipts fulfilled, and alone withdraw that artist's vault                                                                                                         |
| Gas sponsor (optional)       | Openfort embedded-wallet gas policy or a Kora paymaster, per front     | Signs as `payer` on buys and redeems: pays rent and the Core fee, nothing else. Not a protocol role; the program only checks that `payer` signed                                                                                                                        |
| `curve` PDA                  | Program                                                                | Mint `$MOST`, authority of `rewards_vault` and `usdc_vault`                                                                                                                                                                                                             |
| `artist` PDA                 | Program                                                                | Authority of `artist_vault` and update authority of every perk collection                                                                                                                                                                                               |
| `sol_vault`, `treasury` PDAs | Program                                                                | Pay out SOL on sells, withdraw fees                                                                                                                                                                                                                                     |

One hot key holds the first three roles on devnet. This is a deliberate hackathon trade-off. Roadmap: move the upgrade authority and `Config.admin` to a Squads multisig before any mainnet deploy, and add a timelock in front of `set_config`.

## Known limitations

- **Admin trust.** The admin can pause the protocol, change the fee up to 10%, change pass benefits and split floors, and in price mode 0 set the SOL/USD conversion used by USDC buys (bounded in staleness by `max_price_age_secs`, not in value). These changes take effect immediately. Only the admin transfer has a cool-off. The admin cannot touch artist vaults, nor take over an artist through `set_artist(authority)`.
- **Split floors are not retroactive.** Raising `min_burn_bps` / `min_rewards_bps` applies to later `create_perk` / `set_perk` calls; existing perks keep their split until edited.
- **Sponsor exposure.** A sponsor that signs as `payer` pays rent and the Core fee for that instruction, but any other instruction in the same transaction can also spend its SOL. The program cannot protect a sponsor that co-signs without inspecting the transaction; that is the sponsor's policy layer (Openfort gas policy, Kora validation).
- **Upgradeable program.** The upgrade authority can change any behavior. Until the authority is a multisig, users trust the deployer.
- **Sells depend on real SOL reserves.** USDC buys raise the curve price without adding SOL to `sol_vault`. A sell larger than `real_sol_reserves` fails with `InsufficientReserves`. This is a liveness limitation, not a loss of funds; see ARCHITECTURE.md.
- **Locked balances.** No instruction spends `rewards_vault` or `usdc_vault` yet. Tokens and USDC sent there stay there until an upgrade adds a path.
- **Passes are transferable.** Benefits follow the asset owner. A pass can be sold or lent; the program does not freeze it.
- **`init_if_needed` on `buyer_ata` and `kyc`.** The buyer's ATA is standard. `set_kyc` intentionally overwrites an existing record, so the admin can revoke approval.
- **Receipts are permanent.** A `Receipt` is never closed; its rent (about 0.002 SOL) stays locked.
- **No reentrancy surface.** The program makes CPIs only to the System, Token and Metaplex Core programs, all address-constrained.
- **KYC scope.** The gate covers curve buys and sells only (on devnet it is on). SPL transfers, redeems and artist withdrawals are not gated; the country code is stored but not enforced. No personal data is on-chain; see ARCHITECTURE.md 2.11.
- **Placeholder metadata.** Perk and curve URIs point at files the team has not hosted yet (404). This is a presentation gap, not a security one, but a wallet cannot visually verify what it is buying until they exist.
- **Not audited.** Unit tests cover the math; integration tests cover the flows. No third-party review has happened.

## Reporting a vulnerability

Do not open a public issue for a security problem.

1. Contact the maintainers privately through the repository's issue tracker using a confidential issue, or through the team channel listed in the repository's contact information.
2. Include the affected instruction, the cluster, a transaction signature or a reproduction, and the impact.
3. You will get an acknowledgment within 72 hours. Fixes ship to devnet first; the changelog records them.

The program is open source so that reviewers can read the code. Reports that lead to a fix are credited in `CHANGELOG.md` unless you ask otherwise.
