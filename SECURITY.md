# Security

This document covers the Solana program in `programs/mostro`. It states the security model as implemented today, the authorities involved, the known limitations, and how to report a vulnerability.

The program is deployed on devnet only. It has not been audited. Do not deploy it to mainnet in this state.

## Security model

| Property                                        | How the code provides it                                                                                                                                                                                                                                                                                                                                       |
| ----------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Fixed supply                                    | `create_curve` mints the 1,000,000,000 supply once (28 / 7 / 15 / 50 split) and revokes the mint authority in the same instruction (`set_authority(MintTokens, None)`). No instruction, and no upgrade of this program, can mint more without changing the mint account itself                                                                                 |
| Cold reserves behind the multisig               | `artist_reserve`, `mostro_reserve`, `dex_reserve`, `rewards_vault`, the curve USDC vault, `sol_vault`, `treasury` and `treasury_usdc` have no admin withdrawal path. They move only through `execute_token_transfer` / `execute_sol_transfer` on a proposal whose approvals weigh strictly more than 51 % of the live member weight (admins 1, super-admins 2) |
| Executor cannot redirect a proposal             | The executor recomputes the source vault from the proposal's `vault` kind and `curve` (`ProposalMismatch` otherwise) and `destination` is address-constrained to `proposal.destination`. A proposal moves exactly the named amount from the named vault to the named account                                                                                   |
| Membership is governed too                      | Adding, upgrading or removing a member is a `SetMember` proposal under the same threshold; `execute_set_member` refuses to drop the total weight to 0 (`LastMember`). One `Approval` PDA per member per proposal, so a vote cannot be cast twice; proposals expire after `proposal_ttl_secs`                                                                   |
| User transactions need no protocol signer       | PDAs sign every vault transfer, vault burn and Core mint with program seeds (`invoke_signed`). The buyer signs; buys, `redeem_perk` and `buy_perk_sol` also declare a `payer` signer that defaults to the buyer, so the self-paid case still has one signature                                                                                                 |
| Payer / buyer separation                        | `payer` is charged only for rent (`buyer_ata`, `spend`, `receipt`, Core asset) and the Metaplex Core protocol fee. SOL, USDC and tokens always leave `buyer`; tokens and the asset always go to `buyer`; the blacklist and the spend cap are checked against `buyer`. A sponsor cannot redirect a trade by paying for it                                       |
| No sell path                                    | There is no instruction that pays SOL out of `sol_vault` to a user. The primary market is buy-only by construction, not by configuration                                                                                                                                                                                                                       |
| Launch cool-down                                | `create_curve` sets `sale_start_ts >= now + config.launch_cooldown_secs`; buys and hybrid perks before that fail with `SaleNotStarted`. The admin can only push a curve's opening later at creation, never earlier                                                                                                                                             |
| Anti-whale cap                                  | Every curve purchase (SOL, USDC at its SOL equivalent, the curve half of a hybrid perk) is added to `["spend", curve, wallet]` for the current 30-day period and rejected with `SpendCapExceeded` past `config.max_spend_per_period_lamports`. The tracker PDA is seeds-checked, so a wallet cannot present another wallet's counter                           |
| Blacklist that cannot be bypassed               | Buys and redeems take `["blacklist", buyer]` as a seeds-checked account. The client must pass the buyer's own entry (`ConstraintSeeds` otherwise); an existing entry with `blocked == true` fails with `Blacklisted`. Everyone else is allowed, so there is no on-chain identity data                                                                          |
| Circuit breakers                                | `buys_paused` and `redeems_paused` are separate flags. Any governance member can set both at once with `emergency_pause` (one signature, no proposal); only the admin can resume through `set_config`                                                                                                                                                          |
| Fixed economics                                 | Burn 80 % / rewards 20 % are constants (`BURN_BPS`, `REWARDS_BPS`), as are the four allocations; neither the admin nor an artist can change the split. A `const` assertion keeps the allocations summing to the total supply                                                                                                                                   |
| Integer safety                                  | `overflow-checks = true` in release; curve, split and half math run in `u128` with checked operations and return `MathOverflow` instead of panicking. Quotes compare against caller-provided slippage bounds                                                                                                                                                   |
| Fixed protocol accounts                         | `config`, `treasury` and `treasury_usdc` are PDAs with fixed seeds. `initialize_config` can be called once, and only by the program's upgrade authority (`program_data.upgrade_authority_address == payer`), so a stranger cannot front-run initialization                                                                                                     |
| Admin gating                                    | `has_one = admin` on `Config` for every operator instruction. Artist instructions accept the artist's `authority` or the admin, with the exceptions below                                                                                                                                                                                                      |
| Admin-only passes                               | `create_perk` / `set_perk` with `kind == Pass` require `signer == config.admin` (`Unauthorized` otherwise). The Mostro Pass is a platform product; an artist cannot issue one                                                                                                                                                                                  |
| Artist income cannot be redirected by the admin | Hybrid perks pay the artist half to `artist.authority` (address-constrained in `buy_perk_sol`), and `set_artist` may change `authority` only when signed by the current authority. The admin can edit name, URI and active flag but cannot take over an artist                                                                                                 |
| One token per artist                            | `create_curve` requires `artist.curve == default` (`ArtistHasCurve` otherwise) and links the curve to the artist; perks are tied to `artist.curve` (`InvalidMint` otherwise)                                                                                                                                                                                   |
| Perk price cap                                  | `redeem_perk(nonce, max_paid)` / `buy_perk_sol(nonce, max_lamports)` fail with `SlippageExceeded` when the perk price exceeds the caller's cap, so a `set_perk` change cannot overcharge a transaction signed against an older quote                                                                                                                           |
| Perk payment mode                               | Exactly one of `price_tokens` / `price_lamports` is non-zero (`InvalidPerkPrice`), and each instruction refuses the other mode (`WrongPerkPayment`), so a SOL-priced perk can never be taken for free with tokens or vice versa                                                                                                                                |
| Hybrid perk reserve check                       | `buy_perk_sol` requires `artist_reserve.amount >= tokens_from_curve` (`InsufficientReserves`) and applies the curve leg through the same `apply_buy` as a normal buy, so the supply cap and `complete` flag hold                                                                                                                                               |
| Admin rotation with cool-off                    | `propose_admin` starts a timer (`admin_cooloff_secs`); `accept_admin` by the new key succeeds only after it; `cancel_admin_transfer` aborts                                                                                                                                                                                                                    |
| Oracle validation (price mode 1)                | Pyth account key, owner (Pyth receiver program), verification level `Full`, feed id, positive price, staleness (`max_price_age_secs`) and confidence (`conf * 10_000 <= price * 200`, else `PriceUncertain`) are all checked before use                                                                                                                        |
| Admin price expiry (price mode 0)               | The admin value is rejected with `PriceTooOld` when `now - config.price_updated_ts > admin_price_max_age_secs` (must be > 0); a forgotten price cannot keep pricing USDC buys                                                                                                                                                                                  |
| Rent floors                                     | `treasury` and every `sol_vault` are funded with `Rent::minimum_balance(0)` at creation and `execute_sol_transfer` refuses to go below it (`InsufficientReserves`), so the PDAs stay rent-exempt and cannot be reaped                                                                                                                                          |
| Perk integrity                                  | `redeem_perk` / `buy_perk_sol` check `perk.artist`, `perk.mint`, `perk.collection` with `has_one`; the Core collection's update authority is the `artist` PDA, so only this program can mint into it                                                                                                                                                           |
| Replay safety                                   | The asset PDA is seeded by a client nonce; Metaplex Core refuses to create an asset that already exists, so a resent transaction fails instead of double-charging                                                                                                                                                                                              |
| Bounded strings                                 | Name <= 32, symbol <= 10, URI <= 200 bytes, enforced on every write                                                                                                                                                                                                                                                                                            |

## Authorities and keys

| Authority                     | Holder                                                                   | Scope                                                                                                                                                                                                                                                                                                          |
| ----------------------------- | ------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Program upgrade authority     | Deployer keypair (hot key, `~/.config/solana/id.json` of the deployer)   | Can replace the program binary                                                                                                                                                                                                                                                                                 |
| `Config.admin` (operator key) | Same deployer keypair on devnet                                          | Fees (max 10 %), price mode and admin price, Pyth account and feed, both circuit breakers (pause and resume), launch cool-down, anti-whale cap, proposal TTL, blacklist. Creates artists, tokens and Pass perks; edits any artist or perk; marks receipts fulfilled. Cannot move any vault or treasury balance |
| Governance members            | Wallets appointed by proposal; the admin key is the founding super-admin | Propose, approve and execute vault / treasury transfers and membership changes; pull the emergency pause. Weight 1 (admin) or 2 (super-admin); execution needs strictly more than 51 % of the total weight                                                                                                     |
| IDL authority                 | Same deployer keypair                                                    | Can replace the on-chain IDL                                                                                                                                                                                                                                                                                   |
| `Artist.authority`            | Wallet chosen at `create_artist`, changeable by `set_artist`             | Create and edit that artist's Music / Event / Merch perks (not passes), mark receipts fulfilled, receive the artist half of hybrid perk sales in SOL                                                                                                                                                           |
| Gas sponsor (optional)        | Openfort embedded-wallet gas policy or a Kora paymaster, per front       | Signs as `payer` on buys and redeems: pays rent and the Core fee, nothing else. Not a protocol role; the program only checks that `payer` signed                                                                                                                                                               |
| `curve` PDA                   | Program                                                                  | Authority of `curve_vault`, the three reserves, `rewards_vault` and the USDC vault; token metadata update authority. No longer a mint authority after `create_curve`                                                                                                                                           |
| `artist` PDA                  | Program                                                                  | Update authority of every perk collection                                                                                                                                                                                                                                                                      |
| `sol_vault`, `treasury` PDAs  | Program                                                                  | Pay out SOL only on an executed proposal                                                                                                                                                                                                                                                                       |

On devnet one hot key holds the upgrade authority, the operator key and the founding super-admin seat until further members are appointed. Roadmap: move the upgrade authority under a multisig (Squads or this program's own, once it governs upgrades) before any mainnet deploy, appoint the 5 + 5 member set the product spec describes, and consider a timelock in front of `set_config`.

## Known limitations

- **Operator trust.** The admin can pause and resume, change the fee up to 10 %, change the launch cool-down for future tokens, the anti-whale cap, the proposal TTL, the blacklist, and in price mode 0 the SOL/USD conversion used by USDC buys (bounded in staleness, not in value). These changes take effect immediately. The admin cannot move funds: every vault and the treasury need a proposal.
- **Upgradeable program.** The upgrade authority can change any behavior, including the constants above. Until the authority is a multisig, users trust the deployer.
- **Governance quorum is weight, not head count.** A single super-admin with weight 2 passes alone while the total weight is 3 or less; the product's 5 + 5 set (total 15, 8 needed) only holds once those members are appointed. Approvals are weighed when cast and are not retracted when a member is removed; cancel open proposals before removing a member if that matters.
- **Sponsor exposure.** A sponsor that signs as `payer` pays rent and the Core fee for that instruction, but any other instruction in the same transaction can also spend its SOL. The program cannot protect a sponsor that co-signs without inspecting the transaction; that is the sponsor's policy layer (Openfort gas policy, Kora validation).
- **Locked balances until governance acts.** `rewards_vault` (20 % of redeems), the curve USDC vault and `sol_vault` only move through proposals; there is no holder-facing rewards distribution yet.
- **Anti-whale cap is per wallet.** A buyer can split purchases across wallets; the cap limits one wallet per curve per 30-day window, which is what the product asked for, not a sybil defense.
- **Blacklist is reactive.** A wallet is allowed until the admin blocks it. Tokens already held by a blocked wallet are not frozen; SPL transfers are not gated.
- **Passes are transferable.** Benefits are applied by the web app from the pass the wallet holds; a pass can be sold or lent, and the program does not freeze it.
- **`init_if_needed` on `buyer_ata`, `spend`, `blacklist` and `member`.** `set_blacklist` intentionally overwrites an existing entry so the admin can unblock; `execute_set_member` overwrites the role so members can be upgraded, downgraded or removed.
- **Receipts, proposals and approvals are permanent.** None of them is closed; their rent stays locked (about 0.002 SOL each).
- **No reentrancy surface.** The program makes CPIs only to the System, Token, Token Metadata and Metaplex Core programs, all address-constrained.
- **Placeholder metadata.** Perk and token URIs point at files the team has not hosted yet (404). This is a presentation gap, not a security one.
- **Program size.** The binary is about 899 KB against 800,000 bytes reserved on devnet; the next upgrade needs `solana program extend` first (see `programs/mostro/README.md`).
- **Not audited.** Unit tests cover the math; integration tests cover the flows (30 cases on a devnet fork). No third-party review has happened.

## Reporting a vulnerability

Do not open a public issue for a security problem.

1. Contact the maintainers privately through the repository's issue tracker using a confidential issue, or through the team channel listed in the repository's contact information.
2. Include the affected instruction, the cluster, a transaction signature or a reproduction, and the impact.
3. You will get an acknowledgment within 72 hours. Fixes ship to devnet first; the changelog records them.

The program is open source so that reviewers can read the code. Reports that lead to a fix are credited in `CHANGELOG.md` unless you ask otherwise.
